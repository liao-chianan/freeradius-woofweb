第二種驗證方式

裝置不支援主要方式（{{ config.outer }} + {{ config.inner }}）時，會在連線過程中要求改用別的方式；設定第二種方式後，裝置改要這種也接受。 Wi-Fi 一開始仍先提議主要方式的外層，同一次連線內協商，不是失敗後再重試。例如主要方式 PEAP + GTC 給 Windows、Android， 第二種方式 TTLS + PAP 給 iPad。外部 RADIUS 要能驗兩種方式送出的密碼（PAP 與 GTC 送給外部都是 PAP；MSCHAPv2 需要外部支援 MS-CHAPv2）。 立即生效，不需重啟 FreeRADIUS。

帳號黑白名單

比對裝置送出的內層帳號（也就是實際送去外部驗證的帳號，含 @ 之後），「包含」關鍵字即符合，不分大小寫，一行一個。 先看黑名單：符合就拒絕，不轉送。白名單留白表示不限制；有內容時，必須符合其中一個才轉送。例如白名單填 @partner.edu.tw 只允許該網域的帳號。 儲存後立即生效，不需重啟 FreeRADIUS。

裝置數上限

每個外部帳號在一個週期內可登入的裝置數（以 MAC 計算），超過就拒絕，失敗原因是「超過裝置數上限」。 外部 RADIUS 驗證通過後才計數，密碼錯誤或被黑白名單擋下的不算。與 AD、Google 帳號的上限分開計算； 重置週期與「全部重置」沿用系統設定（目前{% if window_hours == 24 %}每天 00:00{% else %}每 {{ window_hours }} 小時{% endif %}，下次重置 {{ next_reset }}）。 同一週期內用過的裝置不受影響；手機隨機 MAC 換了會算新裝置。立即生效，不需重啟 FreeRADIUS。
